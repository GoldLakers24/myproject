How HTTP Works

learn how clients and servers exchange request, responses, and web resources.

The client-server model

A client is a browser or application that asks for information. A server receives the request, processes it, and sends back a response. One server may respond to requests from many clients.

Browser
Client
HTTP request → ← HTTP response

Parts of an HTTP request

An HTTP request tells the server which resource or action the client wants. It commonly contains a method, a request target, headers, and sometimes a body

                        
                            GET /index.html HTTP/1.1 
                            Host: example.com 
                            Accept: text/html

Here, GET asks for a resource, /index.html is the request target, and the Host and Accept lines are headers.

Common HTTP methods

GET

Requests a resource, such as a web page.

POST

Submits data, such as a completed form.

PUT

Replaces a resource with an updated version.

PATCH

Changes part of an existing resource.

DELETE

Requests removal of a resource.

HEAD

Requests response headers without the response body.

Parts of an HTTP response

A response communicates the result of a request. It includes a status code, headers, and often a body containing the requested information.

                        
                            HTTP/1.1 200 OK    
                            Content-Type: text/html

                            <h1>Welcome!</h1>

HTTP status codes

Status codes are three-digit numbers grouped into five categories:

Group Meaning Example
1xx Informational 100 Continue
2xx Success 200 OK
3xx Redirection 301 Moved Permanently
4xx Client error 404 Not Found
5xx Server error 500 Internal Server Error

See HTTP in your browser

Most browsers have Developer Tools. Open the Network panel and reload a page to see requests, status codes, resource types, and loading times. This is a useful way to connect these concepts to real websites.
